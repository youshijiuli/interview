## 9 分布式锁与分布式 ID

### Q38: 什么是分布式锁？为什么需要它？

**答：** 分布式锁用于在**分布式系统**中控制不同进程/服务对共享资源的互斥访问。

**为什么需要分布式锁？**
- 单机锁（如 `threading.Lock`）只在同一 JVM/进程中有效
- 分布式系统中多台服务器可能同时操作同一资源，需要跨进程的锁

### Q39: 如何用 Redis 实现分布式锁？

**答：**

#### 基础版本（SETNX）
```python
import redis

conn = redis.Redis(host='127.0.0.1', port=6379)

# 加锁
def acquire_lock(lock_name, timeout=10):
    """使用 SET NX EX 原子操作加锁"""
    return conn.set(lock_name, 'locked', nx=True, ex=timeout)

# 释放锁
def release_lock(lock_name):
    conn.delete(lock_name)

# 使用
if acquire_lock('order_lock_123', timeout=10):
    try:
        # 处理业务...
        pass
    finally:
        release_lock('order_lock_123')
else:
    print('获取锁失败，稍后重试')
```

#### 避免误删锁（给锁加唯一标识）
```python
import uuid

def acquire_lock_v2(lock_name, timeout=10):
    lock_value = str(uuid.uuid4())
    acquired = conn.set(lock_name, lock_value, nx=True, ex=timeout)
    return lock_value if acquired else None

def release_lock_v2(lock_name, lock_value):
    """使用 Lua 脚本保证删除的原子性"""
    lua_script = """
    if redis.call('get', KEYS[1]) == ARGV[1] then
        return redis.call('del', KEYS[1])
    else
        return 0
    end
    """
    conn.eval(lua_script, 1, lock_name, lock_value)
```

#### Redlock（红锁算法）
在 Redis 集群中使用多个独立的 Redis 实例，加锁时需要超过半数（N/2+1）节点加锁成功才算获取锁成功，解决了单节点 Redis 故障导致的安全问题。

```python
# 使用第三方库
# pip install redlock-py
from redlock import Redlock

dlm = Redlock([{"host": "localhost", "port": 6379, "db": 0}])
lock = dlm.lock("resource", 10000)  # 10秒超时
if lock:
    # 处理业务
    dlm.unlock(lock)
```

### Q40: 什么是分布式 ID？有哪些生成方案？

**答：** 分布式 ID 是分布式系统中用于唯一标识数据的 ID，需要满足：全局唯一、高性能、趋势递增。

| 方案 | 说明 | 优缺点 |
|------|------|--------|
| **UUID** | 128位全局唯一标识符 | 实现简单，但太长、无序（索引性能差） |
| **数据库自增** | MySQL AUTO_INCREMENT | 单点瓶颈，多表不通用 |
| **数据库号段模式** | 一次申请一个号段（如 1-1000），用完再申请 | 减少 DB 访问，但依赖 DB |
| **Redis 自增** | `INCR key` 原子自增 | 高性能，但需持久化防丢 |
| **Snowflake（雪花算法）** | Twitter 开源的 64 位自增 ID 算法 | 高性能、有序、不依赖外部组件 |
| **美团 Leaf、百度 UidGenerator** | 基于 Snowflake 的改进版本 | 解决时钟回拨等问题 |

### Q41: Snowflake（雪花算法）是如何工作的？

**答：** Snowflake 生成的是一个 64 位的 long 型数字：

```
 1bit     41bit            10bit        12bit
┌────┬─────────────────┬───────────┬────────────┐
│未用│   时间戳(毫秒)    │ 机器ID     │ 序列号      │
└────┴─────────────────┴───────────┴────────────┘
```

| 组成部分 | 位数 | 说明 |
|---------|------|------|
| 符号位 | 1 | 固定为 0（正数）|
| 时间戳 | 41 | 当前时间与起始时间的差值（毫秒），可用约 69 年 |
| 机器 ID | 10 | 工作机器 ID（5 位数据中心 + 5 位机器），支持 1024 台 |
| 序列号 | 12 | 同一毫秒内的序列号，支持 4096 个 |

**特点：**
- 全局唯一
- 趋势递增（按时间排序）
- 每毫秒可生成 4096 个 ID
- 不依赖数据库

**Python 实现：**
```python
import time

class Snowflake:
    def __init__(self, worker_id=1, datacenter_id=1):
        self.worker_id = worker_id
        self.datacenter_id = datacenter_id
        self.sequence = 0
        self.last_timestamp = -1

        self.twepoch = 1288834974657  # 起始时间戳（如 2010-11-04）
        self.worker_id_bits = 5
        self.datacenter_id_bits = 5
        self.sequence_bits = 12

    def next_id(self):
        timestamp = int(time.time() * 1000)

        if timestamp < self.last_timestamp:
            raise Exception('时钟回拨')

        if timestamp == self.last_timestamp:
            self.sequence = (self.sequence + 1) & 4095
            if self.sequence == 0:
                # 同一毫秒用完，等待下一毫秒
                while timestamp <= self.last_timestamp:
                    timestamp = int(time.time() * 1000)
        else:
            self.sequence = 0

        self.last_timestamp = timestamp

        return ((timestamp - self.twepoch) << 22) | \
               (self.datacenter_id << 17) | \
               (self.worker_id << 12) | \
               self.sequence
```
