## 10 五险一金知识

### Q42: 五险一金分别是什么？

**答：**

#### 五险（社会保险）

| 险种 | 说明 | 个人缴纳 | 公司缴纳 | 用途 |
|------|------|---------|---------|------|
| **医疗保险** | 看病报销 | 工资的约 2% | 工资的约 8% | 药店买药、医院挂号诊疗拿药，医保内用药报销 80%+ |
| **养老保险** | 退休金 | 工资的 8% | 工资的约 18% | 退休后按月领取 |
| **失业保险** | 失业补助 | 不缴 | 公司全缴 | 最多领 2 年，审核严格 |
| **工伤保险** | 工伤赔付 | 不缴 | 公司全缴 | 上下班途中和工作中的工伤 |
| **生育保险** | 生育补助 | 不缴（已并入医疗） | 公司全缴 | 男女都要交，生育时报销和领津贴 |

#### 住房公积金

| 项目 | 说明 |
|------|------|
| 公积金 | 个人和公司各缴纳工资的 5%-12% |
| 用途 | 买房贷款（利率低）、租房提取、房屋装修 |
| 提取 | 多地支持按月提取 |

### Q43: 医疗保险需要注意什么？

**答：**

- **职工医保**（非常好）：个人钱进医保账户，可以药店买药、医院挂号。医保内用药报销 80%+，自付约 20%。医保外用药不报。公司缴纳部分进入统筹账户
- **居民医保/新农合**：报销比例低，药店拿药不报销
- **享受待遇**：医保交够 6 个月后才能享受
- **退休条件**：一般需要缴满 25 年（部分地方逐渐变为 30 年）
- **社保断缴**：尽量不要断，影响买房资格、车牌摇号、子女入学等

## 11 简历编写

### Q44: 写简历的目的是什么？

**答：** 两个目的：
1. 让 HR/面试官对你产生兴趣
2. 获得面试机会

简历不是写给自己看的，是写给面试官看的。只写对你有用的，可以有润色成分。

---

### Q45: 一份优秀的简历应该包含哪些内容？

**答：** 按重要程度排序：

| 优先级 | 内容 | 说明 |
|--------|------|------|
| 1 | 学历（学校） | 全日制本科 |
| 2 | 工作履历（公司） | 之前的公司和岗位 |
| 3 | 年龄 | 正值当打之年 |
| 4 | 项目经历 | 3 个以上不同技术栈的项目 |
| 5 | 技能点 | 高级技能优先 |
| 6 | 证书/奖项 | 挑重点写 |

**原则：** 写到简历里的东西，取决于写了是否能让人觉得你优秀。

### Q46: 个人信息怎么写？

| 项目 | 建议 |

### Q47: 学历部分怎么写？

**答：**
- 学历写"本科"（全日制）
- 学校：省重点以上可以强调
- 专业：计算机及相关专业
- 毕业时间：需要写
- 课程内容：不需要列
- 学分绩点：不需要
- 奖项：挑特别重点的列几个
- 英语四级：可以写

### Q48: 个人技能怎么写？

**答：** 核心原则：
1. 把比较高级的技能写在前面
2. 即便相同的技能，表述要比别人高级
3. 技能篇幅不能超过项目篇幅
4. 一些低级技能可以融合到项目描述中

**技能写法对比：**

| 普通写法 | 高级写法 |
|---------|---------|
| 熟悉 DRF | DRF 三大认证、频率、权限 |
| 了解 JWT | JSON Web Token 认证 + 自动刷新 |
| 用过 Docker | 自定制 Dockerfile 构建 Redis 基础镜像，目录映射端口映射 |
| 会 docker-compose | docker-compose services 管理多容器编排 |
| 会 Git | Git 分支管理、冲突解决、PR/MR 协作流程 |

**可以列的高级技能点：**
- 内网穿透
- dotenv 环境变量管理
- click 命令行工具
- SQLAlchemy relationship / index / default / 多对多关系
- drf auth/throttle 之 has_permission 定制
- drf 视图家族 - 自定制 ViewSet 混合视图扩展类、路由定制
- 自定制 Dockerfile 构建 Redis 基础镜像
- docker-compose services 管理

### Q49: 项目经历怎么写？

**答：**

**项目数量：** 至少 3 个以上，技术栈尽量各不相同。

**项目名：**

- 用英文名或有辨识度的名字，如 Archry、Spug、Luffy

**项目描述模板：**

```
项目名：Spug
项目时间：2024.01 - 2024.06
所在公司/部门：XX 科技有限公司

项目描述：
Spug 是面向中小型企业设计的轻量级无 Agent 的自动化运维平台，
整合了主机管理、主机批量执行、主机在线终端、文件在线上传下载、
应用发布部署、在线任务计划、配置中心、监控、报警等一系列功能。

技术栈：
Python / Django / DRF / Redis / Celery / MySQL / Docker / Nginx / Ant Design

我的职责与亮点：
- 主机批量执行：多线程 + 队列 + 缓存优化，支持同时管理 500+ 台主机
- 实现了多数据库读写分离配置和数据库连接池优化
- 使用 Redis 实现分布式锁解决任务重复执行问题（附架构图）

```

**项目描述中的技术亮点词汇：**
- Meta class、reflect 反射
- 读写分离、多数据库
- 缓存、分布式锁、分布式 ID
- sentry 异常监控

**加分项：**
- 项目截图、架构图

- 在线演示地址

## 12 面试技巧

### Q52: 面试流程一般是怎样的？

**答：**

```
简历投递 → HR 初筛 → 一面（技术面/同事）→ 二面（技术面/领导）
→ HR 面 → （可能有）CTO/总监面 → 谈薪资 → 发 offer → 背调 → 入职
```

---

### Q53: 一面和二面有什么区别？

| 维度 | 一面 | 二面 |
|------|------|------|
| 面试官 | 同级别同事 / 小组长 | 技术 Leader / 主管 |
| 侧重点 | 技术基础、编码能力 | 项目经验、架构能力、解决问题的能力 |
| 时长 | 30-60 分钟 | 45-60 分钟 |
| 形式 | 基础题 + 算法题 + 项目介绍 | 深挖项目 + 场景题 + 设计题 |

---

### Q54: 如何做自我介绍？

**答：** 1-2 分钟的自我介绍，按以下结构：

```
1. 基本信息（10秒）
   "我叫 XX，XX 城市，XX 年经验 Python 开发"

2. 技术栈简介（20秒）
   "主要用 Python + Django/DRF 做后端开发，前端 Vue 也可以写，
    部署运维也会，能独立负责项目"

3. 项目亮点（40秒，最重要！）
   挑 1-2 个最有含金量的项目，简明说出：
   - 项目是什么
   - 你负责了什么
   - 解决了什么技术难题
   - 取得了什么成果

4. 个人特点（10秒）
   "比较爱钻研技术，团队协作能力好"
```

**注意：**
- 不要背简历
- 不要流水账
- 要引导面试官问你擅长的领域
- 语速适中，有自信

### Q55: 常见面试问题及回答思路

#### 技术基础类
```
Q: 你的技术栈是什么？
A: 不要列一堆，说核心 2-3 个。如："主要做 Python 后端，用 Django/DRF，
    前端 Vue 也会写，部署运维也能搞。"

Q: Python 你用了多久？
A: 如实回答，加上使用深度。"用了 X 年，从基础的 Web 开发到异步任务、部署都有做"
```

#### 项目经验类
```
Q: 介绍一下你最满意的项目
A: 按 STAR 法则回答：
   Situation（背景）：项目是什么场景
   Task（任务）：你要做什么
   Action（行动）：你具体怎么做
   Result（结果）：取得了什么成果

Q: 项目中遇到的最大的挑战？
A: 说一个真实的技术难题 + 你是如何解决的 + 学到了什么
```

#### 陷阱问题
```
Q: 你为什么要离职？
A: 不要诋毁前公司。说："职业发展/个人成长/技术方向"等

Q: 你的缺点是什么？
A: 说真实的但不致命的缺点，并且强调正在改进。
   如："有时太注重代码细节，现在会有意识地平衡质量和效率"

Q: 你期望薪资多少？
A: 提前了解市场行情，给一个范围。"我了解这个岗位的薪资范围是 XX-XX，
    基于我的经验，我期望在 XX 左右"
```

### Q56: 常见的技术面试题

#### Python
```
Q: Python 的 GIL 是什么？
A: GIL（全局解释器锁）是 CPython 中的互斥锁，保证同一时刻只有一个线程在执行。
   多线程在 CPU 密集型任务上无法利用多核，但 I/O 密集型任务仍然有效。
   解决：使用多进程、协程、或换 PyPy/Jython 等没有 GIL 的解释器

Q: 装饰器的原理？
A: 装饰器本质是一个接受函数作为参数的函数，返回一个新的函数。
   利用闭包实现，在不修改原函数的情况下增加功能。
   @语法糖等价于 func = decorator(func)

Q: *args 和 **kwargs 的区别？
A: *args 接收位置参数，打包成元组；**kwargs 接收关键字参数，打包成字典
```

#### Django
```
Q: Django 的中间件（Middleware）是什么？
A: 中间件是 Django 的钩子框架，在请求/响应处理的各个阶段插入自定义逻辑。
   常见用途：用户认证、日志、CORS、异常处理

Q: Django ORM 中 select_related 和 prefetch_related 的区别？
A: select_related 用于一对一/外键，通过 JOIN 一次性查询（SQL 联表）。
   prefetch_related 用于多对多/反向外键，两次查询再 Python 层面拼接
```

#### Redis
```
Q: Redis 为什么快？
A: 1) 基于内存  2) 单线程无锁（6.0+ 网络 I/O 可多线程，命令执行仍单线程）  3) 高效的数据结构  4) I/O 多路复用  5) 协议简单

Q: 缓存和数据库双写一致性如何保证？
A: 常用方案：
   1) 先更新数据库，再删缓存（Cache Aside 模式）
   2) 延时双删：先删缓存 → 更新数据库 → 再延时删一次缓存
   3) 最终一致性：通过 Canal（阿里开源）监听 binlog 更新缓存
```

## 附录：面试连环问示例

以 Redis 缓存为例，面试官的追问路径：

```
Q: 你们项目用 Redis 了吗？

   → 缓存击穿用互斥锁

Q: 布隆过滤器的原理是什么？
   → 基于位图和多个哈希函数...

Q: Redis 挂了怎么办？
   → 我们用了主从 + 哨兵，自动故障转移

Q: 主从复制的原理？
   → RDB 全量 + 增量同步...

Q: 缓存和数据库双写一致性怎么保证？
   → 先更新数据库再删缓存...
```

**面试技巧：** 每个回答都要**留有余地**，让面试官能追问下去。如果你把一个点说死了，面试官只能换一个你不一定熟悉的新话题。
