## 5 MySQL 读写分离

### Q29: 什么是 MySQL 主从复制？

**答：** MySQL 主从复制是将一台 MySQL（Master）的数据实时同步到其他 MySQL（Slave）的技术。

**复制原理（三步走）：**
```
① Master 将所有数据变更写入二进制日志（binlog）
② Slave 的 I/O 线程从 Master 拉取 binlog，写入中继日志（relay log）
③ Slave 的 SQL 线程从 relay log 中读取并回放数据变更
```

**binlog 的三种格式：**

| 格式 | 说明 |
|------|------|
| **STATEMENT** | 记录 SQL 语句（省空间，但部分函数如 NOW() 可能导致不一致） |
| **ROW** | 记录每行数据的变化（推荐，更精确，但日志量大） |
| **MIXED** | 混合模式，一般用 STATEMENT，特殊情况下用 ROW |

### Q30: 如何搭建 MySQL 主从复制（Docker 方式）？

**答：**

**1. 创建主库容器：**
```bash
docker run -d --name mysql_master \
    -p 3307:3306 \
    -e MYSQL_ROOT_PASSWORD=123456 \
    mysql:5.7
```

**2. 配置主库 my.cnf：**
```ini
[mysqld]
server-id=1
log-bin=mysql-bin       # 开启 binlog
binlog-format=ROW       # ROW 格式
```

**3. 创建从库复制用户：**
```sql
CREATE USER 'repl'@'%' IDENTIFIED BY 'repl123';
GRANT REPLICATION SLAVE ON *.* TO 'repl'@'%';
FLUSH PRIVILEGES;

SHOW MASTER STATUS;  -- 记录 File 和 Position
```

**4. 创建从库容器：**
```bash
docker run -d --name mysql_slave \
    -p 3308:3306 \
    -e MYSQL_ROOT_PASSWORD=123456 \
    mysql:5.7
```

**5. 配置从库 my.cnf：**
```ini
[mysqld]
server-id=2
```

**6. 从库配置复制：**
```sql
CHANGE MASTER TO
    MASTER_HOST='主库IP',
    MASTER_PORT=3306,
    MASTER_USER='repl',
    MASTER_PASSWORD='repl123',
    MASTER_LOG_FILE='mysql-bin.000001',  -- 主库 SHOW MASTER STATUS 的 File
    MASTER_LOG_POS=154;                   -- 主库 SHOW MASTER STATUS 的 Position

START SLAVE;
SHOW SLAVE STATUS\G;  -- 检查 Slave_IO_Running 和 Slave_SQL_Running 是否为 Yes
```

## 15 MySQL 面试题补充

### Q71: MySQL 的索引类型有哪些？

| 索引类型 | 说明 |
|---------|------|
| **主键索引（PRIMARY KEY）** | 非空唯一，一张表只有一个，聚簇索引 |
| **唯一索引（UNIQUE）** | 值唯一，可以为 NULL |
| **普通索引（INDEX/KEY）** | 无限制，加速查询 |
| **全文索引（FULLTEXT）** | 用于全文检索 |
| **联合索引（复合索引）** | 多个列组成一个索引，遵循最左前缀 |

**索引底层数据结构（B+ 树）：**
- 非叶子节点只存 key，叶子节点存完整数据
- 叶子节点之间通过双向链表连接（支持范围查询）
- InnoDB 中主键索引的叶子节点存的是完整行数据（聚簇索引）
- 二级索引的叶子节点存的是主键 ID（回表）

### Q72: 什么是索引的最左前缀原则？

**答：** 对于联合索引 `(a, b, c)`，查询条件必须包含最左边的列 `a`，索引才能被使用。

```sql
-- 假设有联合索引 idx_abc (a, b, c)

WHERE a = 1                     -- ✅ 用到索引（a）
WHERE a = 1 AND b = 2           -- ✅ 用到索引（a, b）
WHERE a = 1 AND b = 2 AND c = 3 -- ✅ 用到索引（a, b, c）
WHERE a = 1 AND c = 3           -- ✅ 用到索引（a），c 部分不能用到

WHERE b = 2                     -- ❌ 不能用索引（跳过了 a）
WHERE b = 2 AND c = 3           -- ❌ 不能用索引
WHERE c = 3                     -- ❌ 不能用索引
```

### Q73: 事务隔离级别有哪些？

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
|---------|------|-----------|------|
| READ UNCOMMITTED（读未提交） | 是 | 是 | 是 |
| READ COMMITTED（读已提交）| 否 | 是 | 是 |
| REPEATABLE READ（可重复读）| 否 | 否 | 是（InnoDB 用间隙锁解决） |
| SERIALIZABLE（串行化）| 否 | 否 | 否 |

**三种问题说明：**
- **脏读**：读到了其他事务未提交的数据（可能回滚）
- **不可重复读**：同一事务内两次读同一行数据结果不同（被其他事务 UPDATE 了）
- **幻读**：同一事务内两次查询结果集行数不同（被其他事务 INSERT/DELETE 了）

```sql
-- 查看当前隔离级别
SELECT @@transaction_isolation;

-- 设置隔离级别
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
```

### Q74: MySQL 慢查询如何优化？

**答：**

**1. 开启慢查询日志：**
```sql
SHOW VARIABLES LIKE 'slow_query_log';
SET GLOBAL slow_query_log = ON;
SET GLOBAL long_query_time = 2;  -- 超过 2 秒的记录
SET GLOBAL slow_query_log_file = '/var/log/mysql/slow.log';
```

**2. 分析慢查询：**
```sql
-- 查看慢查询日志
-- 或使用 EXPLAIN 分析执行计划
EXPLAIN SELECT * FROM course WHERE name LIKE '%Python%';
-- 重点关注：type（ALL 是全表扫描，要避免）、key（用了哪个索引）、rows（扫描行数）
```

**3. 常见优化手段：**
- 添加合适的索引（根据 WHERE、JOIN、ORDER BY 条件）
- 避免 `SELECT *`，只查需要的字段
- 避免在 WHERE 子句中对字段进行函数操作（`WHERE YEAR(create_time) = 2024` → 索引失效）
- 避免前导模糊查询（`LIKE '%keyword'` → 索引失效）
- 大表做分页时用子查询优化（`LIMIT 100000, 10`）
- 合理使用 JOIN，小表驱动大表

### Q75: MySQL 行锁和表锁的区别？

| 对比 | 表锁 | 行锁 |
|------|------|------|
| 粒度 | 整张表 | 单行 |
| 并发度 | 低 | 高 |
| 死锁 | 不会 | 可能会 |
| 引擎 | MyISAM（支持） | InnoDB（支持） |

**InnoDB 行锁类型：**
- **共享锁（S 锁/读锁）**：`SELECT ... LOCK IN SHARE MODE`，允许多个事务同时读
- **排他锁（X 锁/写锁）**：`SELECT ... FOR UPDATE`，修改数据时使用
- **间隙锁（Gap Lock）**：锁定索引记录之间的间隙，防止幻读
