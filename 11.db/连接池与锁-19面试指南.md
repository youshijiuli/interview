## 7 数据库连接池

### Q33: 什么是数据库连接池？为什么需要它？

**答：** 数据库连接池是预先创建一定数量的数据库连接，放在一个"池"中供程序复用。

**为什么需要连接池？**
- 数据库连接的创建和销毁成本很高（TCP 握手、认证等）
- 高并发时频繁创建连接会导致性能瓶颈
- 连接池可以限制最大连接数，保护数据库
- 连接复用大大提高系统性能

**Django 中使用连接池：**
```bash
pip install django-db-connection-pool
```

```python
# settings.py
DATABASES = {
    'default': {
        'ENGINE': 'dj_db_conn_pool.backends.mysql',  # 替换默认引擎
        'NAME': 'mydb',
        'USER': 'root',
        'PASSWORD': '123456',
        'HOST': '127.0.0.1',
        'PORT': 3306,
        'POOL_OPTIONS': {
            'POOL_SIZE': 10,           # 连接池大小
            'MAX_OVERFLOW': 10,        # 最大溢出连接数
            'RECYCLE': 3600,           # 连接回收时间（秒）
            'TIMEOUT': 30,             # 等待连接超时
        },
    },
}
```

**连接池核心参数：**
| 参数 | 说明 |
|------|------|
| POOL_SIZE | 核心连接数，保持不释放 |
| MAX_OVERFLOW | 超出核心数后最多再创建几个连接 |
| RECYCLE | 连接最大存活时间，超时回收 |
| TIMEOUT | 等待可用连接的超时时间 |

## 8 悲观锁与乐观锁

### Q34: 什么是悲观锁？什么是乐观锁？

**答：**

#### 悲观锁（Pessimistic Lock）
- **思想**：每次操作数据时都认为别人会修改，所以先加锁
- **实现**：数据库行锁（`select ... for update`）
- **适用**：写多读少、冲突频繁的场景
- **缺点**：锁占用时其他事务等待，吞吐量下降

#### 乐观锁（Optimistic Lock）
- **思想**：每次操作数据时认为别人不会修改，更新时检查是否被改过
- **实现**：版本号 / 时间戳 / CAS
- **适用**：读多写少、冲突少的场景（如秒杀）
- **缺点**：冲突时需要重试

---

### Q35: Django 中如何实现悲观锁？

```python
from django.db import transaction

# 使用 select_for_update 加行锁
with transaction.atomic():
    # 这会加行锁，其他事务要操作同一行会被阻塞直到当前事务提交
    product = Product.objects.select_for_update().get(id=1)
    if product.stock > 0:
        product.stock -= 1
        product.save()
```

def decr_stock(product_id):

class Order(models.Model):

### Q37: Django 事务如何使用？

```python
from django.db import transaction

# 方式一：装饰器
@transaction.atomic
def transfer(from_id, to_id, amount):
    Account.objects.filter(id=from_id).update(balance=F('balance') - amount)
    # 如果下面出错，上面的减钱也会回滚
    Account.objects.filter(id=to_id).update(balance=F('balance') + amount)

# 方式二：上下文管理器
def create_order(user_id, items):
    with transaction.atomic():
        order = Order.objects.create(user_id=user_id)
        for item in items:
            OrderItem.objects.create(order=order, ...)
        # 任何异常都会回滚整个事务

# 方式三：手动控制
with transaction.atomic() as t:
    do_something()
    # 手动回滚
    t.set_rollback(True)
```

**事务的四大特性（ACID）：**

| 特性 | 说明 |
|------|------|
| **原子性（Atomicity）** | 事务中的所有操作要么全部成功，要么全部失败回滚 |
| **一致性（Consistency）** | 事务前后数据保持一致，不违反约束 |
| **隔离性（Isolation）** | 并发事务互不影响 |
| **持久性（Durability）** | 事务提交后数据永久保存 |
